# UI Guide

UI가 있는 프로젝트에서만 작성한다. 디자인 시스템보다 먼저 실제 화면의 목적을 정한다.

## Direction

- 사용자 목적: {이 화면에서 끝내야 하는 일}
- 분위기: {형용사 2개}
- 기준 화면: {있다면 링크 또는 파일}

## Rules

- 장식보다 정보 위계를 우선한다.
- 색상, 간격, 모서리 값은 소수의 토큰으로 반복 사용한다.
- 키보드 사용, 대비, 반응형 레이아웃을 실제 화면에서 확인한다.

## Tokens

- 색상: {배경, 본문, 강조, 성공, 오류}
- 간격: {예: 4px 배수}
- 타이포그래피: {본문과 제목 규칙}
